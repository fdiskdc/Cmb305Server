## 2. 存储与数据边界

- PVE均配置 `local`、`local-lvm`、`tank-zfs`；`tank-zfs` 指向各自的 `tank/pve-data`。
- 常规学生容器系统盘为模板905的链接克隆，样例容量设置为200GiB；模板不能随意销毁或修改。
- 宿主机 `/tank/lab-data/users/<账号>/home`、`work`、`scratch` 绑定到容器的个人数据目录。
- 公共数据来自 `/tank/lab-data/public_data`，只读Dfam库来自 `/tank/public/dfam`。
- 两台抽查样例的home/work/scratch均未设置quota/refquota。未把样例结论扩大为对每个历史容器的保证。
- `zfs list tank` 检查时：服务器1 USED约6.14TiB、AVAIL约6.46TiB；服务器2 USED约1.10TiB、AVAIL约11.5TiB。与 `zpool list` 的池分配统计不是同一口径。
- 两个tank池均ONLINE，未报告已知数据错误。ZFS顶层显示两个数据设备，没有显示mirror/raidz；底层硬件阵列的保护级别未核实，不作磁盘冗余保证。

`shared=1` 是挂载属性标记，不证明网络共享或数据同步。绑定目录数据不会因为做了一份普通 `vzdump` 系统备份就自动进入归档。需要分别记录系统盘备份、个人数据备份和公共数据保障方式。

## 3. 控制器的关键行为

控制器路径：`/usr/local/sbin/pve-labctl`。

两台检查时源码SHA-256一致：

```text
4910f88fd65dfce347b3229f32a2adda784cbbf6a7afd89abcbd6817296fb27a
```

升级后应重新核对行为，不仅检查命令名称是否存在。以下行号对应上述版本。

| 操作 | 源码核验结果 | 对手册的影响 |
| --- | --- | --- |
| 创建 | `create_slot`（约1547行）使用905模板链接克隆，配置数据挂载、资源、网络、账号和登记 | 使用已分配槽位，不单独裸调用pct create |
| 创建失败 | 支持`--keep-on-failure`；保留现场用于排查 | 学生创建示例明确使用此选项 |
| 重建前检查 | `rebuild_preflight`（约2284行）核对槽位所属节点、材料、数据集、挂载和链接克隆 | 布局不匹配就停止，不绕过保护 |
| 重建 | `rebuild_slot`（约2322行）保留home/work/scratch并核对数据集GUID，但可跳过已通过验证的运行实例 | 要执行重建时先正常停机、确认stopped，再单槽位重建 |
| 退役 | `cmd_rollback`（约2508行）删除容器、端口规则及相关登记 | 不是安全撤销命令 |
| 数据清理 | `remove_datasets`（约1224行）默认删除scratch、work；未传purge_home时保留home | 删除章节必须明确两个目录的数据损失 |
| 批量操作 | 存在create-range和rebuild-range等命令 | 学生示例只操作单个槽位，不提供批量删除流程 |
| 外部登记 | 包含MySQL同步；部分失败被记录而不阻断整个操作 | 命令结束后仍需核对实际状态与登记一致 |

`pve-labctl list` 的登记状态不一定等于 `pct status` 的实时状态。`show`、`export`等输出也可能包含不应公开的登记内容，手册仅演示筛选必要字段。

## 5. 后续维护与发布

- 修改模板、控制器、存储或认证方式后，同步更新本手册的核验日期与对应章节。
- 新版高影响命令先在管理员批准的非生产测试对象上验证；明确检查系统盘、数据集、入口和登记四部分。
- 发布前检查明文私钥、密码和验证码密钥均未进入Git暂存区或历史。仓库采用默认忽略、只允许公开文档及加密成品的规则。
- 加密ZIP仅使用明确允许的三份原始材料和内部登录说明，不自动打包整个项目目录。
- 加密包密码取指定密码文件的单行内容，去除行末换行；正文只写“解压密码写在服务器机架上”。
- 每次重建加密包后重新生成 `access/SHA256SUMS`，测试正确密码解密后内容一致，以及错误密码被拒绝。
- AES加密不改变用户口令本身的强度。若管理材料需要轮换，公开仓库历史中的旧加密包不能被视为已撤回，应先轮换实际访问凭据。
