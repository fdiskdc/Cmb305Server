## 1. 先认识三个位置和两种编号

| 名称 | 可以理解为 | 在这里做什么 |
| --- | --- | --- |
| 自己的电脑 | 你的 Windows / macOS 笔记本 | 保存私钥、打开终端、上传下载文件 |
| PVE 宿主机 | 实验室整台物理服务器 | 用 `pct` 管理容器，用 `zfs` 查看存储 |
| 自己的容器 | 分给你的 Linux 工作环境 | 安装科研软件、运行分析、读写自己的数据 |

`root@...` 中的 root 代表 Linux 管理员。宿主机 root 能影响全部容器；容器 root 主要影响该容器内部。运行生物信息分析时，尽量使用分配给自己的普通账号，不在宿主机安装科研依赖或运行分析程序。

终端常见提示符中的 `$`、`#` 不是命令的一部分。本手册代码块不带这些提示符，复制时不需要加它们。输入密码时屏幕不显示字符通常是正常现象。

### 两种编号不能混用

- **CTID / VMID / 容器编号：**PVE 使用的编号，例如管理员分配记录中的某个四位数；`pct status`、`pct reboot` 接受它。
- **槽位 / slot：**实验室管理脚本中的登记编号；`pve-labctl create`、`rebuild-range`、`rollback` 接受它。
- **账号：**容器内的 Linux 用户名，与你的槽位、CTID 都不同。

核验时的编号范围如下，范围仅帮助识别，不代表可自行占用：

| 节点 | 学生槽位 | 常规学生 CTID |
| --- | --- | --- |
| 服务器 1 | 1–50 | 1102–1151 |
| 服务器 2 | 51–100 | 2102–2151 |

两台各有 50 个学生槽位登记。模板、构建环境、试点容器以及旧容器另有编号；不要操作 `200`、`900–905`、`1101`、`2101` 等保留对象。范围外的新编号必须由管理员规划。

## 2. 准备登录材料

从[首页](../README.md)下载 `login-materials.zip`。**解压密码写在服务器机架上。**

包内包含：

| 文件 | 用途 |
| --- | --- |
| `bnu-305server-1` | SSH 私钥，两台宿主机使用同一份材料 |
| `passwd.txt` | 管理页面密码材料；不要把文件名当成密码输入 |
| `pve2f.txt` | PVE 验证器的设置密钥，不是每次登录用的六位验证码 |
| `ACCESS-README.txt` | 完整的 1Panel 安全入口及认证说明 |

采用 AES-256 ZIP 加密。可选用支持该格式的解压软件；若系统解压器不支持，先换兼容工具，不要把文件上传在线解压网站。

把解压后的文件留在自己的受保护目录。不要上传私钥到宿主机、容器、共享网盘的公开链接或代码仓库。不要分享验证器截图。密码与验证器密钥不写进 SSH 配置文件。

本手册的 `./bnu-305server-1` 表示“终端当前目录下的该文件”。如果终端不在解压目录，应先进入该目录，或把 `-i` 后的路径改为自己电脑上的完整路径，路径含空格时加引号。

## 3. 三种宿主机登录方式

### 3.1 SSH：主要操作入口

**执行位置：自己的电脑。** 需要能访问 `192.168.3.181` 或 `192.168.3.191` 所在的实验室内网。

macOS / Linux：打开终端，切换到解压目录，执行：

```bash
chmod 600 ./bnu-305server-1
ssh -i ./bnu-305server-1 -p 8005 root@192.168.3.181
```

Windows：在解压目录打开 PowerShell，执行：

```powershell
ssh -i .\bnu-305server-1 -p 8005 root@192.168.3.181
```

服务器 2 将末尾地址改成 `192.168.3.191`。`-i` 指定私钥，`-p 8005` 指定宿主机 SSH 端口。不要省略端口，也不要把 `8006` 或自己的学生入口端口填进来。

第一次连接会显示主机密钥指纹。先向管理员核对，确认后输入 `yes`。如果提示 `REMOTE HOST IDENTIFICATION HAS CHANGED`，暂停并核实服务器是否重装，不直接删除信任记录或关闭校验。

成功后先确认当前位置：

```bash
hostname
whoami
```

服务器 1 主机名应为 `cmb305server1`，服务器 2 应为 `Cmb305Server2`，用户应为 `root`。若显示 `lab-...`，通常在容器里，应先辨认位置。

退出 SSH：

```bash
exit
```

关闭终端可能中断当前前台运行的程序；它不等于关闭容器。长任务请在自己的容器里使用持久会话工具，并先了解如何恢复会话。

### 3.2 可选：保存 SSH 别名

自己电脑的 SSH 配置文件通常位于 `~/.ssh/config`；Windows 通常为 `$HOME\.ssh\config`。**保留已有配置，追加以下两段**，把密钥路径改成自己的实际路径：

```sshconfig
Host bnu305-s1
    HostName 192.168.3.181
    User root
    Port 8005
    IdentityFile ~/.ssh/bnu-305server-1
    IdentitiesOnly yes

Host bnu305-s2
    HostName 192.168.3.191
    User root
    Port 8005
    IdentityFile ~/.ssh/bnu-305server-1
    IdentitiesOnly yes
```

此示例假定你已将私钥安全地放在自己的 `~/.ssh/` 目录；如果还在解压目录，就填写实际路径。不要把另一位同学的电脑路径照抄进去。

配置后可执行 `ssh bnu305-s1` 或 `ssh bnu305-s2`。容器管理不需要 X11 图形转发，首次使用先保持上述最小配置。

### 3.3 PVE 管理页面

在自己的电脑浏览器打开：

- 服务器 1：`https://192.168.3.181:8006`
- 服务器 2：`https://192.168.3.191:8006`

用户名填 `root`，认证域选择 **Linux PAM standard authentication**；等价身份是 `root@pam`。密码使用加密包中的密码材料。遇到证书提示先确认地址与管理员提供的信息，不把证书问题当成密码错误。

**服务器 1 的二次验证：**在自己手机或受保护设备的验证器中选择“手动输入设置密钥”，将 `pve2f.txt` 的内容作为密钥，类型选基于时间的 TOTP。已核实参数为 SHA1、6 位、30 秒；条目名称可写“BNU305-PVE-服务器1”。登录时输入验证器当时显示的六位数字，不把设置密钥粘贴进验证码框。

这是把已有密钥添加到自己的验证器，不是在 PVE 后台创建新的认证方式。请勿修改其他同学共用的认证设置。

服务器 2 在 2026-11-04 核验时未配置 `root@pam` 的二次验证；没有出现验证码提示不代表操作错误。如果后来要求验证码，先向管理员确认新材料，不假设两台一定使用同一配置。

### 3.4 1Panel 页面

基础地址分别为 `http://192.168.3.181:8004`、`http://192.168.3.191:8004`。**请使用加密包 `ACCESS-README.txt` 中带安全入口路径的完整地址。**

实际配置的用户名为 **`cmb305`**。密码材料见加密包。1Panel 当前使用 HTTP，限在获准的可信内网使用，不自行将入口暴露到公网。

1Panel 主要用于已有宿主机服务管理；本手册的 PVE 容器操作仍以 SSH 命令为准。在 1Panel 中随意修改数据库、Docker、网络或防火墙可能影响多人，普通使用者不要调整这些设置。

## 4. 找到自己的容器和账号

先向管理员取得五项信息：**所在服务器、槽位、CTID、容器账号、学生入口端口**。宿主机 root 密钥不等于你日常科研账号的登录方式；后者以管理员实际分配为准。

**执行位置：PVE 宿主机。**

```bash
pct list
pve-labctl list
```

`pct list` 显示实际运行状态；`pve-labctl list` 显示槽位、账号、CTID、容器 IP、端口和登记状态。登记状态可能滞后，判断是否正在运行以 `pct status` 为准。

下面通过输入框设置自己的 CTID，之后只在当前终端有效：

```bash
read -r -p "请输入管理员分配的容器编号 CTID：" CTID
pct status "$CTID"
pct config "$CTID"
```

看到 `status: running` 表示运行中，`status: stopped` 表示已停止。`pct config` 中重点看 `hostname`、`rootfs`、`mp0` 至 `mp4`、`net0`；核对名称和挂载路径确实属于自己。

查询某个槽位时，使用下列筛选输出，避免把完整登记内容发到群里：

```bash
read -r -p "请输入管理员分配的槽位：" SLOT
pve-labctl show "$SLOT" | python3 -c 'import json,sys; d=json.load(sys.stdin); keys=["slot_id","username","vmid","private_ip","base_port","port_end","status"]; print("\n".join(str(k)+": "+str(d.get(k)) for k in keys))'
```

每个常规学生槽位登记了连续 10 个入口端口。**最小端口 `base_port` 对应容器 SSH 端口 22**；其余端口的用途以管理员交接为准。不要用宿主机 `root` 账号搭配学生端口尝试替代学生账号。

## 5. 启动、进入、退出和重启

以下命令都在 **PVE 宿主机** 执行，`CTID` 已在上一节输入并核对。新开终端要重新输入。

| 任务 | 命令 | 结果与影响 |
| --- | --- | --- |
| 查看状态 | `pct status "$CTID"` | 只查看运行/停止状态 |
| 启动 | `pct start "$CTID"` | 从停止状态启动 |
| 进入容器管理 shell | `pct enter "$CTID"` | 进入容器，通常是容器 root |
| 在容器内执行一条命令 | `pct exec "$CTID" -- hostname` | 输出该容器的主机名 |
| 正常关机 | `pct shutdown "$CTID" --timeout 120` | 请求正常结束，影响所有运行任务 |
| 正常重启 | `pct reboot "$CTID" --timeout 120` | 重启该容器，分析任务可能中断 |
| 强制停止 | `pct stop "$CTID"` | 类似断电，仅在无法正常关机且确认后使用 |

### 从宿主机进入自己的科研账号

```bash
pct enter "$CTID"
```

此时已经在容器中，先执行 `hostname`、`whoami` 核对位置。再执行：

```bash
read -r -p "请输入自己的容器账号：" LAB_USER
su - "$LAB_USER"
pwd
```

通常会进入 `/home/自己的账号`。第一次 `exit` 从普通账号返回容器 root，第二次 `exit` 才从容器返回宿主机；每次不确定时都可用 `hostname`、`whoami` 判断。

### 重启前后怎么检查

1. 确认容器确实属于自己，通知正在使用该容器的同学，保存数据并正常结束分析任务。
2. 在宿主机执行 `pct reboot "$CTID" --timeout 120`。
3. 执行 `pct status "$CTID"`，再执行 `pct exec "$CTID" -- hostname`。
4. 进入普通账号，检查自己的数据目录并运行一个小的分析测试。容器 running 不等于所有科研服务都已恢复。

如果正常关机超时，不要立即连续执行强制停止。先确认是否仍在写入数据。**不要在宿主机直接运行 `reboot`、`shutdown` 或 `poweroff`。**

## 6. 数据放在哪里、如何检查空间

### 6.1 当前存储结构

| 容器内路径 | 实际来源 | 建议用途与注意事项 |
| --- | --- | --- |
| `/`、`/etc`、`/opt`、`/usr/local`、`/root` | 容器系统盘，位于 `tank/pve-data` | 系统及系统级软件；重建可能丢失 |
| `/home/账号` | `/tank/lab-data/users/账号/home` | 个人脚本、环境、重要结果；仍需独立备份 |
| `/work` | `/tank/lab-data/users/账号/work` | 计算输入、运行目录和中间结果 |
| `/scratch` | `/tank/lab-data/users/账号/scratch` | 可重建的临时文件；不要存唯一一份原始数据 |
| `/pubdata` | `/tank/lab-data/public_data` | 多人可写的公共数据；不要清理他人内容 |
| `/db/dfam` | `/tank/public/dfam` | 只读公共数据库 |

这里的“建议用途”是使用约定，不表示已有定时自动清理。核验时未证明 `/scratch` 会自动过期，不要依赖自动清理。

除系统盘外，上述数据目录是宿主机 ZFS 数据集的绑定挂载。容器配置中的 `shared=1` 不会复制文件，也不意味着两台服务器共用同一份数据。

### 6.2 先看可用空间，再看自己的占用

**执行位置：容器内，以自己的普通账号执行。**

```bash
df -hT "$HOME" /work /scratch /pubdata
findmnt -T "$HOME"
du -xhd1 "$HOME"
du -xhd1 /work
du -xhd1 /scratch
```

`df` 看所在文件系统的总量、可用量；`du` 统计目录实际占用。`-h` 用易读单位，`-d1` 只汇总下一层，`-x` 不跨到其他文件系统。`du` 在大目录上可能较慢，不要频繁并行运行，不要为了找一个文件扫描整台服务器。

注意：多名学生可能看到相同的池可用空间。看到几 TiB 可用不表示这些空间全部分给你。样例用户数据集没有单独设置 quota/refquota，系统盘的 `size=200G` 也不限制绑定目录的总数据量。

**执行位置：宿主机，维护人员查看整体。**

```bash
zpool list
zpool status
zfs list -o name,used,avail,quota,refquota,mountpoint tank tank/lab-data tank/lab-data/users
pvesm status
```

`zpool FREE`、`zfs AVAIL` 和 `pvesm` 的容量含义不同，不能混为“每位学生可用容量”。ZFS 快照也会保留旧数据：删除文件后空间未立即释放时，先让管理员检查快照、仍被进程打开的文件和配额，不要自行销毁快照或数据集。

### 6.3 如何整理自己的空间

1. 用上面的 `du` 找到占用最大的**自己的目录**。
2. 区分原始数据、可重建中间文件、软件缓存、最终结果；确认原始数据和关键结果已有独立备份。
3. 停止正在读写这些文件的程序，再按明确的文件名逐项清理。首次清理由熟悉项目的同学确认。
4. 再用 `du`、`df` 查看变化。把文件挪到同一数据池的另一个目录不会释放整个池的空间。

不要清理 `/tank` 根目录，不要删除公共库，不要修改挂载目录权限为全员可写，不要运行复制来的批量删除命令。若分析需要大量磁盘，先估算输入量、临时文件和输出量，再与管理员确认空间预算。

## 7. 先学备份，再做高影响操作

**重建、删除、迁移前需要两类备份：系统盘备份 + 个人数据备份。**`vzdump` 的普通容器备份不包含这里的 home/work/scratch 等绑定挂载数据；只保存一份 `vzdump` 文件不够。

### 7.1 准备备份位置

由管理员提供一个空间足够且权限受控的备份目录，最好位于独立存储。不要直接把大备份写到默认 `/var/lib/vz/dump`：宿主机根文件系统总量约 39 GiB，容易被占满。

以下示例在 **宿主机** 执行。目录必须预先由管理员准备，不能填 `/`、用户数据源目录或会被删除的容器系统盘内路径。

```bash
read -r -p "输入管理员提供的备份目录绝对路径：" BACKUP_DIR
test -d "$BACKUP_DIR"
df -hT "$BACKUP_DIR"
```

`test` 返回非零或 `df` 报错就停止，不继续后续备份。备份目录不应公开可读，因为系统盘和用户目录可能包含账号材料。备份文件即使临时放在同一个 ZFS 池，也只能帮助恢复误操作，不能防止整个池损坏；完成后还需保存一份独立副本。

### 7.2 一致性备份示例

先结束分析任务、记录软件环境，并确认自己的 CTID 和账号。以下代码会**正常关闭一个容器，并保持关闭**，直到你检查备份后自行启动。不要拿其他同学的容器练习。

**执行位置：宿主机。整个括号代码块一次执行；任一步失败会停止该块。**

```bash
(
  set -euo pipefail
  umask 077
  read -r -p "要备份的 CTID：" CTID
  read -r -p "对应容器账号：" LAB_USER
  read -r -p "管理员提供的备份目录绝对路径：" BACKUP_DIR
  [[ "$CTID" =~ ^[0-9]+$ ]]
  [[ "$LAB_USER" =~ ^[a-z][a-z0-9_-]*$ ]]
  [[ "$BACKUP_DIR" = /* && "$BACKUP_DIR" != / ]]
  test -d "$BACKUP_DIR"
  DATA_DIR="/tank/lab-data/users/$LAB_USER"
  test -d "$DATA_DIR/home"
  test -d "$DATA_DIR/work"
  test -d "$DATA_DIR/scratch"
  case "$(realpath "$BACKUP_DIR")/" in
    "$(realpath "$DATA_DIR")/"*) echo "备份目录不能位于待备份数据内"; exit 1 ;;
  esac
  hostname
  pct config "$CTID"
  df -hT "$BACKUP_DIR"
  echo "请核对上方挂载路径是否就是 $DATA_DIR，并确认独立备份空间足够。"
  read -r -p "确认停机备份自己的容器，输入 BACKUP：" CONFIRM
  test "$CONFIRM" = BACKUP
  pct shutdown "$CTID" --timeout 120
  test "$(pct status "$CTID")" = "status: stopped"
  RUN_DIR="$BACKUP_DIR/ct-$CTID-$(date +%Y%m%d-%H%M%S)"
  mkdir -m 700 "$RUN_DIR"
  pct config "$CTID" > "$RUN_DIR/container.conf"
  vzdump "$CTID" --mode stop --compress zstd --dumpdir "$RUN_DIR"
  tar --acls --xattrs --numeric-owner -cpf "$RUN_DIR/personal-data.tar" \
      -C "$DATA_DIR" home work scratch
  tar -tf "$RUN_DIR/personal-data.tar" > /dev/null
  (
    cd "$RUN_DIR"
    sha256sum ./*.tar.zst ./personal-data.tar ./container.conf > SHA256SUMS
    sha256sum -c SHA256SUMS
  )
  echo "备份目录：$RUN_DIR"
  echo "容器仍保持停止。请检查归档、独立副本及恢复条件后再决定启动。"
)
```

该示例适用于已核实的常规学生目录布局。已有额外挂载、改变用户名或目录结构的容器要先调整方案；不要绕过失败检查。`tar` 校验只能证明归档可读，`sha256sum` 只能发现文件内容是否发生变化，都不能替代一次独立恢复测试。

`/pubdata`、`/db/dfam` 不在上述个人数据归档里。依赖公共数据时，记录目录、版本及必需文件，并确认管理员有公共数据备份。不要把整个公共库重复复制进每个人的备份。

确认备份后，可在宿主机另行输入自己的 CTID，再执行 `pct start "$CTID"`。如果接下来要重建或迁移，按对应章节保持停止。

<a id="08"></a>
## 8. 创建已分配的容器

### 8.1 本平台为什么使用管理脚本

`pct create` 是 PVE 的底层创建命令；本平台已有编号为 `905` 的冻结模板，学生容器实际通过 `pve-labctl` 调用 `pct clone` 创建。脚本还配置账号、home/work/scratch 数据集、网桥、10 个端口转发以及登记信息。

因此，本平台标准学生容器按**槽位**创建，不能只运行 `pct create` 或随意克隆一个新编号就算完成。不要删除或修改模板，不要对冻结模板直接安装软件。

### 8.2 创建前提

- 管理员已分配本台服务器上一个允许创建的槽位，并确认原使用者已完成交接。
- 该槽位对应的 CTID 当前不存在。现有停止状态的容器应使用 `pct start`，不属于“未创建”。
- 若是回收槽位，必须确认旧 home 和其他遗留数据的归属；创建会重新挂载既有数据，不能把上一位学生的 home 直接交给新学生。
- 管理员已检查容量与配套服务。当前不是一个可任意新增第 101 个槽位的流程；扩容需另行规划。

**执行位置：管理员指定的 PVE 宿主机。**

```bash
(
  set -euo pipefail
  read -r -p "输入已获分配且允许创建的槽位数字：" SLOT
  [[ "$SLOT" =~ ^[0-9]+$ ]]
  CTID="$(pve-labctl show "$SLOT" | python3 -c 'import json,sys; print(json.load(sys.stdin)["vmid"])')"
  pve-labctl show "$SLOT" | python3 -c 'import json,sys; d=json.load(sys.stdin); print({k:d.get(k) for k in ["slot_id","username","vmid","base_port","status"]})'
  if pct config "$CTID" >/dev/null 2>&1; then
    echo "该 CTID 已存在；停止创建，请检查是否只需启动。"
    exit 1
  fi
  read -r -p "管理员已确认分配与遗留数据处理，输入 CREATE：" CONFIRM
  test "$CONFIRM" = CREATE
  pve-labctl create "$SLOT" --keep-on-failure
  pct status "$CTID"
  pct config "$CTID"
  pve-labctl list
)
```

`--keep-on-failure` 表示失败时保留现场，供管理员检查。不要添加 `--force` 绕过空间保护，也不要把单槽位示例扩展成批量操作。

成功应包括：容器 running、挂载与分配账号一致、能进入自己的普通账号、预期入口可访问、登记状态更新。脚本返回成功也不保证外部数据库同步一定成功；看到同步警告要交给管理员，不能为了刷新列表重新创建容器。

<a id="09"></a>
## 9. 重置：重设密码与重建系统

“重置”不是一个统一动作，先确定你想解决什么问题。

| 需求 | 处理方式 | 数据影响 |
| --- | --- | --- |
| 某个程序卡住、系统需要重新启动 | 正常重启容器 | 内存任务中断，磁盘文件通常保留 |
| 忘记自己的 Linux 登录密码 | 容器内 `passwd` | 修改该账号密码，不重装系统 |
| 系统级环境损坏，需要回到模板 | 备份后重建系统盘 | 系统盘重建；个人绑定数据按脚本保留 |
| 想删除所有个人数据后重新开始 | 管理员单独处理 | 不属于本节保留数据的重建流程 |

### 9.1 重设自己的 Linux 密码

**宿主机：**`pct enter "$CTID"` 进入自己的容器。随后在**容器内**执行：

```bash
read -r -p "需要重设密码的本人账号：" LAB_USER
passwd "$LAB_USER"
```

按提示输入两次新密码，输入不回显。不要修改宿主机 root 密码，也不要修改共享管理账号密码。这只修改 Linux 密码，不自动修改 VNC、网页应用或外部账号登记；若需要同步，由管理员处理。

### 9.2 保留个人目录、重建容器系统

重建会删除并重新生成容器系统盘，包括系统级软件、自定义 `/etc` 配置，以及未放到绑定目录中的文件。必须先按第 7 节完成两类备份。

脚本设计上保留 home/work/scratch，但这不等于每个文件都绝对不变：初始化仍可能更新账号或应用配置。home 内的 Conda 环境、隐藏配置和个人脚本也会留下，因此“保留数据重建”不等于清空所有科研环境。

本节仅适用于控制器管理的标准学生槽位和预期链接克隆布局。脚本有前置检查；发现挂载或系统盘不符合预期时应停止，不绕过检查。

**关键细节：**`rebuild-range` 可能跳过已运行且通过当前模板验证的容器。为明确执行重建，下面流程先正常停机并确认 stopped，再针对**一个槽位**调用它。

**执行位置：对应 PVE 宿主机。先完成备份，再执行整个括号块。**

```bash
(
  set -euo pipefail
  read -r -p "输入自己的槽位数字：" SLOT
  [[ "$SLOT" =~ ^[0-9]+$ ]]
  CTID="$(pve-labctl show "$SLOT" | python3 -c 'import json,sys; print(json.load(sys.stdin)["vmid"])')"
  hostname
  pct config "$CTID"
  read -r -p "已核对对象、完成系统和个人数据独立备份，输入 REBUILD：" CONFIRM
  test "$CONFIRM" = REBUILD
  if [ "$(pct status "$CTID")" = "status: running" ]; then
    pct shutdown "$CTID" --timeout 120
  fi
  test "$(pct status "$CTID")" = "status: stopped"
  pve-labctl rebuild-range "$SLOT" "$SLOT"
  pct status "$CTID"
  pct config "$CTID"
  pve-labctl list
)
```

开始和结束使用同一个槽位数字，表示只重建一个槽位。不要扩大范围，不要用 `rollback` 代替重建。重建失败时保持现场，保存最后的报错并联系管理员；不要反复尝试删除数据集。

成功后检查 home/work/scratch 及项目关键文件，重新连接个人入口、核对软件版本并运行小样本分析。账号材料以管理员最新交付为准，不把初始化输出截图公开。

<a id="10"></a>
## 10. 删除容器与毕业交接

### 10.1 先分清两种删除

- `pct destroy` 主要处理 PVE 容器和系统盘，不能保证清理实验室端口规则、槽位登记及个人数据。
- `pve-labctl rollback` 是本平台的退役操作：停止并删除容器、移除该槽位端口转发、更新登记，**同时删除 work 和 scratch 数据集**。默认保留 home。

**不要因为命令名里有 rollback，就把它理解成可撤销的恢复操作。**`--purge-home` 还会删除 home 及相关父数据集，本手册不把它作为学生自助操作。

### 10.2 删除前检查

1. 确认退役的是自己的槽位和 CTID，而不是模板、试点或其他同学的容器。
2. 正常结束任务，完成系统盘及 home/work/scratch 备份，把关键数据另存到独立位置并验证能读取。
3. 确认交接人能访问所需代码、数据和环境说明；核对公共目录中的成果归属。
4. 与管理员确认 home 保留后的负责人和保留期限。保留 home 不代表它已经有异地备份，也不代表槽位可以直接转交下一位学生。

**执行位置：对应 PVE 宿主机。仅在上面四项都完成后执行。**

```bash
(
  set -euo pipefail
  read -r -p "输入已获批准退役的槽位数字：" SLOT
  [[ "$SLOT" =~ ^[0-9]+$ ]]
  CTID="$(pve-labctl show "$SLOT" | python3 -c 'import json,sys; print(json.load(sys.stdin)["vmid"])')"
  hostname
  pct config "$CTID"
  echo "将删除该容器及 work、scratch；默认保留 home。"
  read -r -p "独立备份和交接已完成，输入 DELETE：" CONFIRM
  test "$CONFIRM" = DELETE
  if [ "$(pct status "$CTID")" = "status: running" ]; then
    pct shutdown "$CTID" --timeout 120
  fi
  test "$(pct status "$CTID")" = "status: stopped"
  pve-labctl rollback "$SLOT"
  pct list
  pve-labctl list
)
```

脚本部分底层删除采用“报错后继续”的实现，**不能只看最后一行成功提示**。操作后由管理员核对 CTID 已消失、端口转发已清除、work/scratch 删除结果、home 保留情况及数据库登记；如果不一致，应保留记录并排查，不能重新运行整段命令“碰碰运气”。

不要为了释放剩余空间自行运行 `zfs destroy`、删除 `/tank/lab-data/users` 或重置整个存储池。

<a id="11"></a>
## 11. 迁移到另一台服务器

两台服务器目前是独立节点，不存在可直接套用的集群内迁移流程。`pct migrate` 不作为本部署的日常迁移入口。

先阅读[迁移与交接](迁移与交接.md)，选择：

- **迁移科研数据和环境：**使用目标服务器上合法分配的容器，转移自己的数据，重建或验证软件环境。这适合多数学生交接。
- **迁移完整容器系统：**保留旧系统盘、用户身份和系统配置，同时处理独立数据集、目标网段、端口、UID/GID 及控制器登记，由管理员执行。

两种方式都应先验证目标，再决定是否退役源容器。不要把两台同名路径当成同一份文件，也不要直接覆盖已有目标学生容器。

## 12. 常见问题

| 现象 | 先检查 | 下一步 |
| --- | --- | --- |
| `Identity file ... not accessible` | 密钥路径、当前目录、文件名 | 用自己电脑的实际路径；不要复制他人的本地路径 |
| `UNPROTECTED PRIVATE KEY FILE` | 私钥访问权限 | macOS/Linux 用 `chmod 600`；Windows请管理员协助检查文件ACL |
| `Permission denied (publickey)` | 是否 root、端口8005、正确私钥 | 不连续猜密码，联系管理员核对授权 |
| SSH连接超时 | 是否接入实验室内网、IP与端口 | 分别确认181/191；请管理员检查主机和网络 |
| 主机密钥变更警告 | 地址是否正确、主机是否重装 | 与管理员核对新指纹，不关闭主机校验 |
| `pct: command not found` | 是否在自己电脑或容器里 | 返回PVE宿主机；无需在容器安装PVE |
| `pct status`说不存在 | CTID、所在服务器、是否把槽位当CTID | 用`pct list`与登记表交叉核对 |
| 登记显示running，但PVE显示stopped | 登记可能滞后 | 以`pct status`判断，先找停止原因 |
| PVE密码错误 | 用户root、Linux PAM、密码材料 | 不把1Panel用户名或TOTP密钥填进去 |
| PVE验证码错误 | 手机自动时间、六位码是否过期、验证器条目 | 确认材料适用该服务器；不自行删除二次验证 |
| 1Panel基础地址打不开登录页 | 是否使用加密包内完整安全入口 | 当前用户名是cmb305，协议为HTTP |
| 创建提示VMID已存在 | 是否已有停止的容器 | 需要启动就用`pct start`；不删除旧容器强行创建 |
| 重建提示跳过 | 容器是否仍运行且已通过模板验证 | 按第9节先备份、正常停机，再进行单槽位重建 |
| `No space left on device` | `df -hT`、`df -i`、个人占用、ZFS配额 | 停止继续产出大文件，保留结果并联系管理员 |
| 删除文件后空间没变 | 仍被程序打开、快照、同池移动 | 不自行删除快照，让管理员检查 |
| 重建后旧Conda问题仍在 | 环境是否在保留的home里 | 单独重建自己的科研环境，别误以为整个home已清空 |
| 配置存在但网页登记不更新 | 同步服务与数据库状态 | 交给管理员排查；不重复创建或删除容器 |

求助时提供：服务器1或2、自己的槽位与CTID、执行位置、命令、时间和最后几行错误。**不要附上私钥、密码、验证码密钥、完整账号导出或安全入口截图。**
