# 迁移与交接

> 本章依据 2026-11-04 的只读配置核验和管理源码分析编写。下列备份、传输、恢复和校验操作**未在实际迁移中执行验证**；文中没有迁移成功截图或成功承诺。

迁移前先联系管理员。学生负责整理软件环境、停止任务和验收；管理员负责目标分配、备份恢复、权限、登记与入口切换。不要自行删除或覆盖任何容器。

日常操作及备份、删除规则请同时参阅[学生使用手册](./学生使用手册.md)。

## 1. 先选择迁移范围

| 路径 | 搬迁内容 | 适用情况与限制 |
| --- | --- | --- |
| 推荐：个人文件迁移与环境重建 | `/home/<账号>`、`/work`、`/scratch`，以及软件环境清单 | 在合法的新目标中恢复文件、重建软件并测试；**不等于完整容器迁移** |
| 高级：完整容器系统盘恢复 | `vzdump` 系统备份，以及另外备份的绑定目录 | 管理员设计 `pct restore` 的存储、挂载、网络和身份映射；不能承诺一键恢复 |

如果软件安装在 `/root`、`/opt`、`/usr/local`，或依赖系统配置，仅复制三个个人目录不会带走这些内容。先由管理员记录并决定重装还是走高级路径。

### 已核验的边界

- 服务器 1：`192.168.3.181`；服务器 2：`192.168.3.191`；两台宿主机 SSH 端口均为 `8005`。
- 两台都是独立的 PVE 9.2.2，未组成 corosync 集群；本环境使用 LXC，没有 QEMU 虚拟机。不能套用集群在线迁移操作。
- 两台均有名为 `tank-zfs` 的存储，指向各自的 `tank/pve-data`。同名不代表数据互通，挂载配置中的 `shared=1` 也不代表实际共享。
- 服务器 1 的槽位 1–50 对应 CT 1102–1151；服务器 2 的槽位 51–100 对应 CT 2102–2151。每台 50 个学生槽位均已创建并登记，**不能假设有空位**。
- `pve-labctl` 管理槽位、端口、账号和数据库。裸用 `pct clone` 或 `pct destroy` 不能保证登记同步；不要据此分配或退役槽位。
- 两个节点的 VMID、用户名、容器 IP 和入口端口并非相同。宿主机 SSH 的 `8005` 不能当作学生容器入口端口。

| 宿主机目录 | 容器内位置 | 迁移处理 |
| --- | --- | --- |
| `/tank/lab-data/users/<账号>/home` | `/home/<账号>` | 单独备份与迁移 |
| `/tank/lab-data/users/<账号>/work` | `/work` | 单独备份与迁移 |
| `/tank/lab-data/users/<账号>/scratch` | `/scratch` | 单独备份与迁移，清理须另行确认 |
| `/tank/lab-data/public_data` | `/pubdata` | 公共可写数据，不随个人目录自动搬迁；管理员另行协调 |
| `/tank/public/dfam` | `/db/dfam` | 公共只读数据，由管理员在目标核验挂载和版本 |

这些宿主机绑定目录的数据不包含在普通 `vzdump` 容器备份里。容器系统盘备份和个人数据备份必须分别保留。

## 2. 管理员先分配目标，学生再整理环境

管理员必须通过管理流程分配合法的全新目标，或确认某个已登记目标可供本次迁移且为空白；没有合适目标就先停止迁移准备中的写入步骤。

交接记录至少包含源/目标宿主机、VMID、账号、三个数据目录、实际入口、挂载配置、负责人及回退安排。记录中含有私人信息或内部配置的部分保存在受控位置，不提交公开仓库。

管理员还需核实非特权容器的 `unprivileged`、`lxc.idmap`、容器内账号 UID/GID，以及宿主机目录的数字属主。用户名相同也不保证数字身份相同。检查目标磁盘容量、配额、公共目录和基础软件。

学生在**源容器终端**执行以下环境整理示例。提示中填写管理员确认的账号；输出写到个人家目录。

```bash
ENV_DIR="$HOME/migration-env"
mkdir -p "$ENV_DIR"
id > "$ENV_DIR/identity.txt"
uname -a > "$ENV_DIR/system.txt"
command -v conda python python3 R Rscript > "$ENV_DIR/program-paths.txt"
```

根据实际使用的软件选择执行，不存在的工具无需安装来凑清单。

```bash
# 在每个实际使用的 Conda 环境激活后分别导出，使用不同文件名。
read -r -p '当前环境的记录名称：' ENV_NAME
conda env export > "$ENV_DIR/$ENV_NAME.full.yml"
conda env export --from-history > "$ENV_DIR/$ENV_NAME.history.yml"
python -m pip freeze > "$ENV_DIR/$ENV_NAME.pip.txt"
Rscript -e 'write.csv(installed.packages()[,c("Package","Version")], stdout(), row.names=FALSE)' \
  > "$ENV_DIR/r-packages.csv"
```

记录常用分析命令、软件版本、数据库版本和一份已知结果的小样本。Conda 文件可能包含旧路径和 `prefix:`；在目标重建前检查。环境清单不是软件包或运行结果的备份。

同时列出定时任务、后台服务、正在运行的分析、项目绝对路径、符号链接和系统级安装。文件中可能含令牌或私有源地址，审阅后保存，勿放进公开手册。

## 3. 停写并生成两类备份

先等待或按软件要求结束分析，停止自动上传、定时任务和服务，记录最后一次输出。关闭会写文件的交互会话；由管理员确认无写入后制作备份。只关终端不一定会停止后台任务。

下面的命令均由**管理员在源宿主机**执行。备份位置需有足够空间，并采用权限受控的专用目录；不要放在公共目录。

```bash
read -r -p '已确认的源 VMID：' SRC_CT
read -r -p '已确认的源账号：' SRC_USER
read -r -p '专用备份目录的绝对路径：' BACKUP_DIR
SRC_BASE="/tank/lab-data/users/$SRC_USER"
# 先人工核对变量、容器配置、属主和容量，确认路径无误再继续。
pct config "$SRC_CT"
stat -c '%u:%g %n' "$SRC_BASE"/{home,work,scratch}
du -sh "$SRC_BASE"/{home,work,scratch}
df -h "$SRC_BASE" "$BACKUP_DIR"
```

备份目录由管理员提前创建，限定只有授权人员可访问。`du` 是容量参考；归档大小、压缩比例和所需剩余空间不能靠它精确保证。若存在嵌套挂载、稀疏文件或特殊 ACL，管理员应另行核实归档范围和恢复能力。

使用[学生使用手册第7节](./学生使用手册.md#07)的一致性备份代码块：先正常关闭源容器并确认 stopped，再备份系统和个人数据。该流程生成一个独立的 `ct-编号-日期时间` 目录，其中包括系统备份 `vzdump-lxc-…tar.zst`、`personal-data.tar`、`container.conf` 和 `SHA256SUMS`。

把这个**本次生成的子目录**作为下文的源备份目录，不能选它的父目录或另一位同学的备份。源容器在迁移期间保持停止；不要只依赖 `vzdump --mode stop`，因为该工具可能在结束后恢复原来的运行状态。管理员检查备份成功、归档可读和独立副本后再继续。

`--numeric-owner` 只记录原始数字身份，不会自动适配目标账号。管理员还应保存源配置和挂载清单到受控交接记录。系统备份只用于高级恢复或回退，不要在推荐路径中直接覆盖新目标。

## 4. 学生通过个人电脑分两段传输

本步骤由已获得宿主机管理权限的同学执行，可使用已交付的 root 私钥；其他使用者由管理员提供范围受限的临时传输账号，或请管理员代为完成。无论哪种方式，都不要把个人电脑上的 root 私钥复制进任何服务器。

先检查个人电脑剩余空间能够容纳完整备份及余量，目标接收目录也有足够空间；两个目录均应为本次迁移专用。管理员提供确认过的文件名、目录和授权账号。

下面在**个人电脑终端**运行。先按提示选择真实的源/目标宿主机；不是让源和目标同时操作同一目录。

下面示例适用于 macOS / Linux 上已获 root 授权的操作者。所有目录预先准备，路径使用无空格的专用路径；私人密钥始终留在本机。整个括号块一次执行，失败就停止。

```bash
(
  set -euo pipefail
  read -r -p '源宿主机（192.168.3.181 或 192.168.3.191）：' SRC_HOST
  read -r -p '目标宿主机（另一台）：' DST_HOST
  [[ "$SRC_HOST" = 192.168.3.181 || "$SRC_HOST" = 192.168.3.191 ]]
  [[ "$DST_HOST" = 192.168.3.181 || "$DST_HOST" = 192.168.3.191 ]]
  test "$SRC_HOST" != "$DST_HOST"
  read -r -p '本机私钥文件的完整路径：' KEY_FILE
  read -r -p '本次源备份子目录绝对路径：' SRC_BACKUP
  read -r -p '目标接收目录绝对路径：' DST_INBOX
  read -r -p '本机空白暂存目录绝对路径：' LOCAL_STAGE
  read -r -p '本次系统备份文件名：' SYSTEM_FILE
  test -f "$KEY_FILE"
  test -d "$LOCAL_STAGE"
  test -z "$(ls -A "$LOCAL_STAGE")"
  df -h "$LOCAL_STAGE"
  read -r -p '已确认本机和目标容量足够、目标接收目录专用，输入 COPY：' CONFIRM
  test "$CONFIRM" = COPY
  for FILE in personal-data.tar container.conf SHA256SUMS "$SYSTEM_FILE"; do
    scp -i "$KEY_FILE" -P 8005 "root@$SRC_HOST:$SRC_BACKUP/$FILE" "$LOCAL_STAGE/"
  done
  scp -i "$KEY_FILE" -P 8005 "$LOCAL_STAGE/personal-data.tar" \
    "$LOCAL_STAGE/container.conf" "$LOCAL_STAGE/SHA256SUMS" "$LOCAL_STAGE/$SYSTEM_FILE" \
    "root@$DST_HOST:$DST_INBOX/"
)
```

Windows PowerShell 示例（所有提示均填写管理员已确认的信息）：

```powershell
$SrcHost = Read-Host "源宿主机内网IP"
$DstHost = Read-Host "目标宿主机内网IP"
if ($SrcHost -notin @("192.168.3.181", "192.168.3.191") -or $DstHost -notin @("192.168.3.181", "192.168.3.191") -or $SrcHost -eq $DstHost) { throw "源和目标必须是两台不同的实验室服务器" }
$KeyFile = Read-Host "本机私钥完整路径"
$SrcBackup = Read-Host "本次源备份子目录绝对路径"
$DstInbox = Read-Host "目标接收目录绝对路径"
$LocalStage = Read-Host "本机空白暂存目录完整路径"
$SystemFile = Read-Host "本次系统备份文件名"
if (-not (Test-Path -LiteralPath $KeyFile -PathType Leaf)) { throw "私钥不存在" }
if (-not (Test-Path -LiteralPath $LocalStage -PathType Container)) { throw "暂存目录不存在" }
if (Get-ChildItem -LiteralPath $LocalStage -Force) { throw "暂存目录不为空" }
if ((Read-Host "已确认两端容量和专用接收目录，输入 COPY") -ne "COPY") { throw "已取消" }
$Files = @("personal-data.tar", "container.conf", "SHA256SUMS", $SystemFile)
foreach ($File in $Files) {
    scp -i $KeyFile -P 8005 "root@${SrcHost}:$SrcBackup/$File" "$LocalStage/"
    if ($LASTEXITCODE -ne 0) { throw "下载失败，停止" }
}
foreach ($File in $Files) {
    scp -i $KeyFile -P 8005 (Join-Path $LocalStage $File) "root@${DstHost}:$DstInbox/"
    if ($LASTEXITCODE -ne 0) { throw "上传失败，停止" }
}
```

使用临时传输账号时，由管理员将上面的 `root` 和认证方式替换为实际授权；不要凭空创建一个新账号。Windows 的 `tar -tf` 可查看归档列表；不要在个人电脑解包再打包后冒充保留 Linux 权限的备份。

个人电脑仅中转归档原文件。若下载中断，保留源备份并重新完成传输；不要因为文件名已出现就认为传输结束。SSH 首次连接时通过管理员核对主机指纹，不关闭主机身份检查。

**不要在个人电脑运行同时带两个远端的普通 `rsync` 命令**；它不支持这种源、目标写法。两个宿主机也不一定持有个人电脑使用的密钥。

## 5. 管理员核验归档、恢复数据

以下在**目标宿主机**执行；先仅校验，不向目标数据目录解包。

```bash
(
  set -euo pipefail
  read -r -p '目标接收目录绝对路径：' DST_INBOX
  cd "$DST_INBOX"
  sha256sum -c SHA256SUMS
  tar -tf personal-data.tar
)
```

校验单列出的三个文件必须全部通过。检查归档只包含预期的 `home/`、`work/`、`scratch/`，不存在越界路径、意外挂载内容；必要时检查详细列表和符号链接。校验单应来自刚才受信的备份通道。

管理员再次确认目标属于本次迁移、三个目录为空白、目标容器保持停写。仅当源/目标宿主机数字属主与容器 UID/GID 映射兼容时，管理员才可在已核对的目标个人数据父目录恢复归档，保留 numeric owner、ACL 和扩展属性。

若身份不兼容，先在受控临时位置解包，制定明确的源/目标 UID/GID 映射并转换，再接入目标。不要对整个 `/tank` 或公共目录递归改属主。

仅在**身份映射一致、归档可信且检查通过、目标三个目录确实为空**时，管理员可执行下面的恢复示例。新建容器的home可能已有初始化文件，因此本段可能主动拒绝；此时管理员应先备份目标初始配置并制定合并方案，不要为通过检查而清空目录。

```bash
(
  set -euo pipefail
  read -r -p '目标 CTID：' DST_CT
  read -r -p '目标学生账号：' DST_USER
  read -r -p '目标接收目录绝对路径：' DST_INBOX
  [[ "$DST_CT" =~ ^[0-9]+$ ]]
  [[ "$DST_USER" =~ ^[a-z][a-z0-9_-]*$ ]]
  DST_BASE="/tank/lab-data/users/$DST_USER"
  test "$(pct status "$DST_CT")" = "status: stopped"
  pct config "$DST_CT"
  for PART in home work scratch; do
    test -d "$DST_BASE/$PART"
    test -z "$(find "$DST_BASE/$PART" -mindepth 1 -maxdepth 1 -print -quit)"
  done
  (cd "$DST_INBOX" && sha256sum -c SHA256SUMS)
  read -r -p '已人工核对目标挂载、UID/GID映射和归档路径，输入 RESTORE-DATA：' CONFIRM
  test "$CONFIRM" = RESTORE-DATA
  tar --acls --xattrs --numeric-owner --same-owner --keep-old-files \
    -xpf "$DST_INBOX/personal-data.tar" -C "$DST_BASE"
)
```

此代码不会启动容器，`--keep-old-files` 用于拒绝覆盖已存在文件。发生错误就停止，恢复后仍需检查属主、权限和源/目标目录差异。不要使用它解开来历不明的归档。

**恢复归档不包含系统盘恢复。** 新目标的系统软件由管理员安装，学生使用环境清单重建所需环境；家目录账号变化、硬编码路径、Conda 前缀和符号链接需逐项处理，不能承诺直接搬过去就能运行。

## 6. 只读复核、试跑、切换和交接

管理员在停写状态下比较源/目标三个目录的相对文件名、大小和校验和，并确认数字属主映射、权限、ACL、扩展属性及符号链接。下方管理员附录给出 checksum dry-run 的示例；归档哈希相同只证明归档传输一致，不能替代恢复后检查。

学生用目标账号确认：家目录、`/work`、`/scratch` 可按预期读写；`/pubdata` 的公共写权限符合安排；`/db/dfam` 保持只读且所需数据可用。不要通过改写公共数据库来测试。

用一份已知输入的小样本运行完整分析，记录软件版本、命令、退出状态和输出差异。涉及随机性的软件固定种子或采用项目认可的误差范围；没有通过就保留原入口并排查。

验收通过后，由管理员通过 `pve-labctl` 配套流程更新账号、槽位、端口及数据库登记，提供确认后的新入口。学生更新自己的连接配置和项目路径，并确认新入口确实进入目标容器。

交接记录需勾选以下项目：

- [ ] 源/目标对应关系、操作者、备份时间与文件位置已记录。
- [ ] 系统盘与个人目录分别备份，归档和恢复后数据校验均有记录。
- [ ] UID/GID、挂载、公共数据、软件环境和小样本验证通过。
- [ ] 管理登记和实际入口一致，学生已从新入口完成登录。
- [ ] 源容器和源数据保留，但旧任务、旧入口写入和自动任务已关闭。
- [ ] 保留期、验收负责人、回退条件及后续退役审批已约定。

回退不能简单把旧入口打开：若目标已经产生新结果，先停写并协调这些新增数据的回收，防止双向写入冲突。到保留期结束后另行批准退役；删除容器、数据集和备份属于独立操作，本章不提供删除命令。

## 附录 A：管理员使用宿主机间 rsync

适合数据量较大、不便在个人电脑完整暂存时。下列示例由管理员在目标宿主机拉取源目录；不是在个人电脑 `rsync` 中写两个远端。

前置条件：目标只用于本次迁移且三个目录为空白；源已停写、备份已完成；UID/GID 映射一致；两端已安装 `rsync`；**管理员已确认目标能访问源宿主机 SSH 8005，并且已有获批准的认证方式**。个人电脑上有密钥不代表宿主机上有同样的认证条件。不要复制 root 私钥；条件不满足就用正文的分段归档路径，不临时搭建转发通道。

以下仅由管理员在**目标宿主机**操作；源认证账号需有读取数据及其元数据的权限，目标执行者需有保留这些元数据的权限。首次连接应核对源宿主机指纹。

```bash
read -r -p '源宿主机（192.168.3.181 或 192.168.3.191）：' SRC_HOST
read -r -p '源宿主机获批准的读取账号：' SRC_ADMIN
read -r -p '源学生账号：' SRC_USER
read -r -p '目标学生账号：' DST_USER
SRC_BASE="/tank/lab-data/users/$SRC_USER"
DST_BASE="/tank/lab-data/users/$DST_USER"
SSH_CMD="ssh -p 8005"
# 先人工检查路径、空白目标和所有权限；账号及路径须无空格。
for part in home work scratch; do
  rsync -aHAXn --numeric-ids --itemize-changes -e "$SSH_CMD" \
    "$SRC_ADMIN@$SRC_HOST:$SRC_BASE/$part/" "$DST_BASE/$part/" || break
done
```

`-n` 是预演，不传文件。逐项审阅输出，确认没有误选目录、权限问题或目标旧数据。源目录结尾的 `/` 表示复制目录里的内容；去掉它可能额外套一层目录。不要加 `--delete`。

确认预演成功、目标仍为空白且专属本次迁移后，管理员才执行真实传输：

```bash
for part in home work scratch; do
  rsync -aHAX --numeric-ids --itemize-changes -e "$SSH_CMD" \
    "$SRC_ADMIN@$SRC_HOST:$SRC_BASE/$part/" "$DST_BASE/$part/" || break
done
```

任何目录失败立即停止后续验收，检查并记录错误。`--numeric-ids` 只适用于已核实的映射一致场景。分目录传输不能保留跨这三个目录的硬链接关系；若有这种依赖，采用正文的单一归档方案或让管理员另行设计。

最后保持停写，执行只读 checksum 复核：

```bash
for part in home work scratch; do
  rsync -aHAXnc --numeric-ids --itemize-changes -e "$SSH_CMD" \
    "$SRC_ADMIN@$SRC_HOST:$SRC_BASE/$part/" "$DST_BASE/$part/" || break
done
```

`-c` 会读取两边文件计算校验和；`-n` 保证不修改目标。所有命令成功且没有预期外差异才算通过。这个命令不会报告仅存在于目标的额外文件，管理员仍需另行比较文件清单；校验时目标尚未开始试跑。完成后由管理员撤销本次迁移的临时授权。

## 附录 B：完整容器系统盘迁移的管理边界

完整路径为：源停写 → `vzdump` 系统备份 + 三个目录独立备份 → 分段传输与哈希核验 → 管理员设计目标恢复 → 数据与身份校验 → 小样本验收 → 更新登记和入口。

管理员使用 `pct restore` 前，必须现场核验目标 VMID、现有资源和登记状态，决定系统盘 `rootfs` 的目标存储、每个 `mp` 的源路径及挂载属性、`net` 的目标网络参数，并审查启动钩子等配置。两边存储同名不等于可以原样套用配置。

把旧系统恢复到新账号槽位，可能保留旧账号、旧家目录、UID/GID、服务配置、网络配置和旧控制器登记引用；目标入口也不会因此自动更新。管理员必须明确保留身份还是转换身份，并逐项调整、校验 `pve-labctl` 的管理关系。

### B.1 先恢复成停机、断网的待验收容器

以下为管理员使用的**离线恢复模板**，参数已对照本机PVE9.2.2帮助核实，但没有做真实迁移演练。它不会启动容器或自动配置学生入口，也不会完成控制器登记。

前置条件：

1. 管理员选定完全未占用的新CTID，且明确它是待验收对象，不覆盖现有学生槽位。
2. 备份已校验，源容器保持停机；审核 `container.conf`，确认是标准五个绑定挂载、仅net0的布局，检查额外设备、hookscript和资源限制。非标准布局另行制定参数。
3. 目标的三个人数据集已单独恢复并通过校验，UID/GID映射适配旧系统，源账号将原样保留。下面 `TARGET_BASE` 指向它们的父目录；不能指向另一位学生的数据。
4. 目标公共目录及版本已核实。存储空间足够，系统盘容量至少满足源系统盘实际需要。

**执行位置：目标PVE宿主机。**

```bash
(
  set -euo pipefail
  read -r -p '管理员批准且未占用的新CTID：' NEW_CTID
  read -r -p '系统备份文件的绝对路径：' SYSTEM_ARCHIVE
  read -r -p '保留的源容器账号：' SRC_USER
  read -r -p '目标已恢复个人数据父目录的绝对路径：' TARGET_BASE
  read -r -p '目标系统盘容量GiB（源标准配置为200，按实际审核）：' ROOT_GIB
  [[ "$NEW_CTID" =~ ^[0-9]+$ ]]
  [[ "$SRC_USER" =~ ^[a-z][a-z0-9_-]*$ ]]
  [[ "$ROOT_GIB" =~ ^[1-9][0-9]*$ ]]
  [[ "$SYSTEM_ARCHIVE" = /* && "$TARGET_BASE" = /* ]]
  test -f "$SYSTEM_ARCHIVE"
  test ! -e "/etc/pve/lxc/$NEW_CTID.conf"
  test ! -e "/etc/pve/qemu-server/$NEW_CTID.conf"
  for PART in home work scratch; do test -d "$TARGET_BASE/$PART"; done
  test -d /tank/lab-data/public_data
  test -d /tank/public/dfam
  hostname
  pvesm status
  echo "将创建停止、网卡断开且不自启的待验收容器，不覆盖旧容器。"
  read -r -p '已核对备份、目标目录、身份、资源和登记方案，输入 RESTORE-SYSTEM：' CONFIRM
  test "$CONFIRM" = RESTORE-SYSTEM
  pct restore "$NEW_CTID" "$SYSTEM_ARCHIVE" \
    --rootfs "tank-zfs:$ROOT_GIB" \
    --mp0 "$TARGET_BASE/home,mp=/home/$SRC_USER,shared=1" \
    --mp1 "$TARGET_BASE/work,mp=/work,shared=1" \
    --mp2 "$TARGET_BASE/scratch,mp=/scratch,shared=1" \
    --mp3 /tank/lab-data/public_data,mp=/pubdata,shared=1 \
    --mp4 /tank/public/dfam,mp=/db/dfam,ro=1,shared=1 \
    --net0 name=eth0,bridge=vmbr1,ip=manual,ip6=manual,link_down=1 \
    --onboot 0 --start 0 --unique 1
  pct status "$NEW_CTID"
  pct config "$NEW_CTID"
)
```

显式传入 `--rootfs` 与各 `--mp` 使用高级恢复方式，避免把备份中的旧绑定路径直接照搬到目标节点。此命令不使用 `--force`，不会以强制覆盖方式复用已有容器。系统盘恢复完成不等于个人目录数据也已恢复，后者必须满足前置条件。

### B.2 再完成身份、网络和控制器接管

保持停止状态，管理员逐项处理：目标主机可用CPU及内存限制；旧系统里的用户、组、家目录和服务配置；目标网桥、容器IP、网关和新入口端口；PVE配置中的额外挂载或设备。确认后才允许启用网络与启动。

控制器目前没有一个已核实的跨节点“接管任意恢复容器”命令。不能把旧账号系统直接塞进另一个学生槽位，再期待 `pve-labctl verify` 自动修好。需要管理员为该对象明确VMID、账号、数据集与槽位的映射，并通过经过审核的登记流程接管；**不要随意运行 `import-plan`、直接改数据库或复制源节点整份状态数据库。**

若不能落实这一步，完整系统恢复只能停留在待验收状态，应选择正文的个人文件迁移与环境重建路径。只有系统盘、绑定数据、身份、软件、入口与管理登记全部通过验收，才可以称为完成该容器的迁移；只复制个人文件应记录为“个人数据迁移与环境重建”。
