# 191 服务器管理员手册（公开版）

本手册面向接管 191 的管理员。执行前从受控交接记录取得 191 专属入口、身份和目标工单。文中的 `<…>` 是占位符，带 `$` 的命令参数须先用交接记录或工单里的值设置。每个代码块按标注位置逐步执行，任一关键结果与登记不符即停。命令和示范映射均经本机资料对照，服务器实时状态和变更结果须在获批作业时核验。

## 第一章　领取 191 入口资料

[191 管理入口资料 · GitHub Releases](https://github.com/fdiskdc/Cmb305Server/releases)

打开项目发布页，在对应版本的 Assets（附件）中查找 191-login-materials.zip。页面尚未列出该文件时，请向交接负责人领取。管理员本人到机房物理机查看解压密码，用支持 AES-256 的本地工具解压，先读 README.txt，再打开 191-access.txt 查看入口。

SSH 身份、PVE 与 1Panel 的个人账号口令及适用的二次验证材料，由交接负责人按权限另行发放。

## 第二章　资源分配说明

以下资源规则适用于 191 的正式用户容器。2026 年 11 月 27 日，管理员核对了全部 50 个正式容器（CTID 2102–2151）的配置与运行时限额。

### CPU：并行任务共用 94 个逻辑 CPU

宿主机预留 2 个逻辑 CPU。其余 94 个（编号 2–95）由正式容器共享。各容器的 CPU 权重均为 100，未设单容器 CPU 时间硬上限。机器空闲时，单个任务可以使用较多 CPU；多个容器同时满载时，调度器按相同权重分配 CPU 时间。

安排任务时，把进程数和每个进程的线程数一起考虑。例如，同时运行 4 个样本、每个样本开 8 个线程，就可能有 32 个计算线程竞争 CPU。

### 内存：按并发峰值安排任务

宿主机预留 16 GiB 内存，容器共享池上限约 3.80 TiB。单个正式容器最多可使用共享池的 95%（约 3.61 TiB），Swap 为 0。其他任务已经占用的内存会减少当前任务可用的容量。

先用一个代表性样本估算峰值内存，再决定同时运行多少个样本，并为桌面和后台进程留出余量。长时间的高并发或大内存作业，宜提前与值班管理员协调运行窗口。

### 存储：个人数据、系统盘和外部存储分别计算

每个正式账号的 home、work、scratch 三个目录合计使用 1 TB。用户可自行安排三处用量，管理员按合计值核算。当前这项实验室管理额度由管理员核查；ZFS 尚未对正式账号设置 1 TB 硬配额，系统显示的池可用空间可能大于个人额度。

系统盘每容器独立限额 200 GiB，单独计量。正常挂载的 /storage/panfs3、/storage/panfs4 上的数据也单独计量，191 侧不另设个人容量上限。大批量写入前，先确认目标路径仍是外部挂载点，并核对项目目录权限。

**管理员核对示例（在 191 宿主机执行）**

```bash
pct config 2102 | grep -E '^(cores|cpulimit|cpuunits|memory|swap):'
findmnt --mountpoint /storage/panfs3 -o TARGET,SOURCE,FSTYPE
findmnt --mountpoint /storage/panfs4 -o TARGET,SOURCE,FSTYPE
```

## 第三章　连接宿主机 SSH 与 PVE

### 3.1 登录宿主机 SSH

**在管理电脑操作。** 取得专属 SSH 账号、管理地址及端口、获准使用的密钥或其他认证方式，并通过交接负责人取得服务器主机公钥指纹。使用密钥时，先限制密钥文件权限，再发起 SSH 连接。

```bash
chmod 600 '<191专属私钥文件>'
ssh -i '<191专属私钥文件>' -p '<191宿主机SSH端口>' '<191管理账号>@<191宿主机地址>'
```

首次连接先核对主机指纹。进入后运行 `hostname -s`，和受控记录核对，再使用获准的宿主机管理身份。主机名或指纹不符时停止。第四章的 `9000` 是示范学生账号的用户 SSH 端口。

### 3.2 登录 PVE 并处理二因素提示

1. 在管理电脑浏览器打开 `<191 PVE HTTPS 入口>`。如遇证书警告，先向交接负责人核对主机和证书指纹。核验一致后再按交接要求继续。
2. 输入交接发放的 191 PVE 账号和口令。原稿记录的认证域为 **Linux PAM**。以交接时确认的账号和认证域为准，登录后在节点树核对 191 节点和当前身份。
3. **PVE 二因素启用状态待本机资料验证。** 原稿描述了 TOTP 登录流程，另一份配置核验记录记载 191 在当次核验时未配置。确认 191 当前状态和新账号的适用方式后再签收，保持现有认证配置。
4. 如确认启用 TOTP，在本人受保护设备的本地验证器中添加基于时间的条目，命名为 `191 PVE`。选择手动输入，导入经确认仅属于该 191 账号的设置密钥。需要手工设置时，对照交接参数，原稿示范为 `SHA1`、`6` 位、`30` 秒。开启设备时间自动同步。PVE 出现 TOTP 提示后，输入验证器生成的当前动态码。接近换码时等下一组再输入。验证器中的设置密钥仅用于本地导入。

PVE 界面用于查看节点、容器状态及任务日志。正式学生容器的创建、重建和退役按第六章走宿主机控制器。

### 3.3 登录 1Panel

在管理电脑浏览器打开交接提供的 `<191 1Panel 完整安全入口>`，输入 `<191 1Panel 账号>` 和对应口令。界面如要求确认许可协议，经阅读确认后再继续。登录后在概览页核对 191 主机身份及资源信息。完整入口、账号、口令和访问范围须分别确认。资料记录了安全入口配置，完整登录及口令可用性待交接核实。若该账号还要求二因素，先确认方式和参数，再按 3.2 的本地导入原则，为 1Panel 建立独立条目并使用经确认的 191 专属材料。1Panel 的二因素配置和参数尚未核实。

## 第四章　定位用户容器、重置密码与恢复桌面

### 4.1 在 191 宿主机核对五字段

示范映射为 **191 → 槽位 `51` → CTID `2102` → `<用户账号>` → 用户 SSH 基准端口 `9000`**。`pve-labctl` 用数字槽位，`pct` 用 CTID。每次都独立核对登记、实时容器与用户账号，端口只在 191 的上下文中用于匹配。

```bash
LAB_USER='<工单中的用户账号>'
hostname -s
pve-labctl list | awk -v u="$LAB_USER" '$2 == u {print $1, $2, $3}'
pve-labctl show 51
pct status 2102
pct config 2102 | grep -E '^(hostname|rootfs|mp[0-9]+|lxc.mount.entry):'
```

示范账号应在登记中唯一对应槽位 `51`、CTID `2102` 和基准端口 `9000`，且实际容器名、个人挂载和工单相符。`show` 输出可能含私密字段，只在受保护终端查看。登记为空、多条匹配、状态矛盾或目标已停机时先核查。若确认处于 `running`，再执行 `pct exec 2102 -- hostname` 核对容器内部主机名。只知道端口时，先让值班人用 191 的受控登记反查账号，再按上述过程复核。

### 4.2 按密码类型分开处理

先验证请求人及账号归属，确认其需要重置的是 SSH 登录密码还是 VNC 密码。以下两条流程均以目标容器已运行、五字段核验通过为前提。

**SSH 登录密码。** 在 191 宿主机的获准管理终端执行下列命令。

```bash
CTID=2102
LAB_USER='<已核对的用户账号>'
pct exec "$CTID" -- hostname
pct exec "$CTID" -- passwd "$LAB_USER"
```

按终端提示交互输入新密码，并安排用户通过受控方式领取及验证 SSH 登录。用户使用其个人账号及端口，示范端口为 `9000`。

**VNC 密码。** 先在 191 宿主机进入容器，再切换到目标用户运行 `vncpasswd`。

```bash
# 191 宿主机
pct enter 2102
```

```bash
# 容器内，核对 hostname 后切换身份
hostname
su - '<已核对的用户账号>'
```

```bash
# 已切到目标用户，先核对 whoami
whoami
vncpasswd
```

按交互提示设置密码。常规可操作桌面在询问是否另设仅查看密码时选择 `n`。退出用户 shell 和容器 shell 后，按 4.3 恢复服务并请用户验证。

### 4.3 恢复 VNC 和网页桌面

**在用户自己的容器 SSH 会话中操作，以该用户身份执行。** 用户 SSH 正常、桌面服务被停用时，先核对主机名和身份，再逐条执行。

```bash
hostname
whoami
sudo systemctl start "lab-vnc@$USER" "lab-novnc@$USER"
systemctl is-active "lab-vnc@$USER" "lab-novnc@$USER"
```

若刚修改 VNC 密码，先让用户保存桌面工作，经同意后把 `start` 改成 `restart` 并再次检查状态。两项均显示 `active` 后，请用户从其个人网页桌面入口连接并验证 VNC 密码及桌面可操作性。网页桌面端口为用户 SSH 基准端口加 `2`，独立 VNC 端口加 `1`。完整用户入口从受控登记领取。

## 第五章　191 存储巡检

先在 **191 宿主机** 查 ZFS 健康、根文件系统余量、数据集容量以及两项 NFS 挂载。`$POOL`、`$NFS_MOUNT_1`、`$NFS_MOUNT_2` 分别填写本机登记的池名和两条绝对挂载路径。`findmnt --mountpoint` 校验指定挂载点是否真实存在，避免把父文件系统当成共享盘。

```bash
hostname -s
pct list
zpool status -x
df -h /
zfs list "$POOL"
findmnt --mountpoint "$NFS_MOUNT_1" -o TARGET,SOURCE,FSTYPE
findmnt --mountpoint "$NFS_MOUNT_2" -o TARGET,SOURCE,FSTYPE
```

两项共享存储的目标、来源和协议应与受控基线一致。宿主机两项通过且确认示范容器 `2102` 正在运行后，继续从 **191 宿主机** 核对容器中的挂载，再用获授权的用户身份在授权目录做一次小范围试读。

```bash
pct exec 2102 -- findmnt --mountpoint "$NFS_MOUNT_1" -o TARGET,SOURCE,FSTYPE
pct exec 2102 -- findmnt --mountpoint "$NFS_MOUNT_2" -o TARGET,SOURCE,FSTYPE
```

挂载缺失、来源异常、池降级、空间告警或读操作卡住时，记录宿主机和容器两侧的结果，通知相关用户暂停向受影响路径写入。存储端疑似无响应时停止重复访问目录。`findmnt` 通过后仍须完成授权试读，才能确认业务可用。

## 第六章　备份、重建、退役与迁移

本章的示范参数为 `SLOT=51`、`CTID=2102`、`BASE_PORT=9000`。实际作业按获批工单填写变量，禁止直接对示范容器执行重建、退役或恢复覆盖。每次先核对第四章五字段、模板和挂载基线，登记容器原状态，取得用户停写与停机确认。正式学生容器的生命周期由 `pve-labctl` 管理。现行备份计划、保存期限及成功试恢复记录需由接任人独立确认。

### 6.1 系统盘与个人数据分别备份并试恢复

**在 191 宿主机的获准管理终端操作。** 设置 `BACKUP_ROOT` 为本次批准使用的独立备份盘目录，`USER_DATA_DIR` 为目标用户的宿主机个人数据父目录，`CTID` 为已复核目标。先检查下面的设备、容量和三个目录，再创建本次备份目录和执行停机。

```bash
findmnt -T "$BACKUP_ROOT" -o TARGET,SOURCE,FSTYPE
df -hT "$BACKUP_ROOT"
ls -ld "$USER_DATA_DIR"/{home,work,scratch}
RUN_DIR="$BACKUP_ROOT/ct-${CTID}-$(date +%Y%m%d-%H%M%S)"
mkdir -p -m 700 "$RUN_DIR"
pct config "$CTID" > "$RUN_DIR/container.conf"
pct shutdown "$CTID" --timeout 120
pct status "$CTID"
```

确认备份盘设备正确、目标目录受保护，且容器已 `stopped`。`vzdump` 保存系统盘，个人绑定数据用单独归档保存。共享远端存储由相应责任人另行确认保护范围。

```bash
vzdump "$CTID" --mode stop --compress zstd --dumpdir "$RUN_DIR"
tar --acls --xattrs --numeric-owner -cpf "$RUN_DIR/personal-data.tar" \
  -C "$USER_DATA_DIR" home work scratch
(cd "$RUN_DIR" && sha256sum ./*.tar.zst personal-data.tar container.conf > SHA256SUMS)
(cd "$RUN_DIR" && sha256sum -c SHA256SUMS)
```

校验单各项均须通过。在 191 宿主机对个人数据做隔离试恢复，`TEST_PARENT` 为批准的独立测试父目录。先预览归档，确认仅有预期的三棵目录树，没有越界路径、意外链接或额外挂载来源，再解到空目录。

```bash
cd "$RUN_DIR"
tar -tf personal-data.tar | cut -d/ -f1 | sort -u
RESTORE_DIR=$(mktemp -d "$TEST_PARENT/ct-restore-XXXXXXXX")
tar --acls --xattrs --numeric-owner --same-owner --keep-old-files \
  -xpf personal-data.tar -C "$RESTORE_DIR"
stat -c '%n  %u:%g  %a' "$RESTORE_DIR"/{home,work,scratch}
```

核对数字 UID/GID、文件权限、ACL、扩展属性和关键文件。需要逐文件比对时，在源端停写期间对三个目录分别执行 `rsync -aHAXnc --numeric-ids --delete --itemize-changes`，保留 `-n`。系统盘试恢复另用获批的独立 CTID 按 6.4 的隔离条件处理。例行备份且原状态应运行时，按工单执行 `pct start "$CTID"` 并请用户验证；后续紧接重建或迁移时保持停机。

### 6.2 重建单个容器系统盘

**在 191 宿主机的获准管理终端操作。** 重建会替换系统盘，需重装用户自行添加的系统软件和配置。流程应保留 `home`、`work`、`scratch` 三个数据集。完成双备份及试恢复核验后，再对已批准的目标逐步执行。

```bash
pve-labctl show "$SLOT"
pct config "$CTID" | grep -E '^(hostname|rootfs|mp[0-9]+):'
pct shutdown "$CTID" --timeout 120
pct status "$CTID"
```

确认状态为 `stopped`、存储和挂载符合基线后，起止槽位填写同一个已审批槽位。

```bash
pve-labctl rebuild-range "$SLOT" "$SLOT"
pve-labctl verify "$SLOT"
pct status "$CTID"
pct config "$CTID" | grep -E '^(hostname|rootfs|mp[0-9]+|lxc.mount.entry):'
```

核对三项个人数据仍在、属主与挂载正常。待容器运行后按第五章核对共享存储，请用户验证 SSH、网页桌面和关键文件，再核对控制器与交接登记。遇到空间、内存、锁或数据集异常时保留原报错，停止强制重试。

### 6.3 按批准范围退役

**在 191 宿主机的获准管理终端操作。** 工单应载明保留范围。先完成双备份及试恢复，确认成果已移交且接收人已验证关键文件。依 6.2 核对并优雅停机，确认已停，再按批准范围执行下列一条。

- **常规退役**使用 `pve-labctl rollback "$SLOT"`。清理系统盘、端口规则、`work` 和 `scratch`，保留 `home`。
- **获书面批准的彻底清除**使用 `pve-labctl rollback "$SLOT" --purge-home`。还会删除 `home` 和用户父数据集，无法通过控制器撤销。

退役完成后，逐项核对。`USER_DATASET_ROOT` 为 191 登记的个人数据集父级，`LAB_USER` 为已核对用户。

```bash
pct list | awk -v id="$CTID" '$1 == id'
zfs list -r "$USER_DATASET_ROOT/$LAB_USER"
for port in "$BASE_PORT" "$((BASE_PORT + 1))" "$((BASE_PORT + 2))"; do
  iptables -t nat -S | grep -w "$port"
done
pve-labctl list | awk -v u="$LAB_USER" '$2 == u {print $1, $2, $3, $4}'
```

确认 CTID 消失，旧目标的端口规则已撤除，个人数据集和宿主机目录符合获批保留范围，控制器与交接登记一致。彻底清除时须核对的是目标数据集确已不存在。若控制器报同步失败，记录并交由获准管理员核对，原流程支持 `pve-labctl mysql-sync`。发现残留时保留日志逐项处理，禁止重复执行销毁命令碰运气。

### 6.4 迁移个人工作环境与对端交接

1. **交接双方确认。** 在受控工单中核对源与目标的身份、获批槽位和 CTID、用户归属、三项目录、数字 UID/GID 映射、挂载与软件版本、接收容量和权限、变更窗口及回退期限。对端由其负责人确认停写或空接收目录、备份与校验单、目标接管和验收责任。191 管理员执行 191 一侧的操作。
2. **191 为源时。** 在 191 宿主机按 6.1 制作双备份及 `SHA256SUMS`，交付完整的受控备份目录和校验单，保留源端停写。**191 为目标时。** 核对目标已有获批账号及槽位、个人目录为空、容器停写，建立本次专用接收目录。管理电脑可按交接安排将收到的整套归档原样上传到 191。`STAGED_RUN` 指收到且位于本机私有目录的备份目录，其他变量取 191 专属交接值。

   ```bash
   scp -P "$SSH_PORT" -i "$KEY_FILE" -r "$STAGED_RUN" \
     "$SSH_USER@$SSH_HOST:$DST_INBOX/"
   ```

3. **191 为目标时在 191 宿主机校验与恢复。** `RECEIVED_RUN` 指接收目录中的本次备份子目录，`DST_USER_DIR` 指已确认空白并停写的目标个人数据父目录。先查接收盘、校验单和归档目录结构，再确认目标挂载、数字属主映射兼容，按 6.1 的试恢复标准核验后方可恢复到目标。

   ```bash
   cd "$RECEIVED_RUN"
   sha256sum -c SHA256SUMS
   tar -tf personal-data.tar | cut -d/ -f1 | sort -u
   ```

   ```bash
   tar --acls --xattrs --numeric-owner --same-owner --keep-old-files \
     -xpf personal-data.tar -C "$DST_USER_DIR"
   stat -c '%n  %u:%g  %a' "$DST_USER_DIR"/{home,work,scratch}
   ```

4. **验收后切换写入。** 核对文件、数字属主、权限、共享挂载和软件环境，请用户在目标端验证 SSH、网页桌面、读写及小样本任务。双方签收后只启用一处写入。若需回退，先停目标写入并交接新增数据，再按约定恢复源。保留期到期后另行批准退役。

完整系统盘恢复仅用于无法在目标复现的系统级环境，由技术维护人另行制定参数。191 接收时，应检查 `pct` 与 `qm` 命名空间均无占用，核对备份、系统存储、绑定挂载、用户映射、网桥与端口规划。资料中的标准布局使用 `pct restore` 并显式指定 `--rootfs`、`--mp0` 至 `--mp4`，目标 `--net0` 带 `link_down=1`，附 `--onboot 0 --start 0 --unique 1`。实际存储、挂载和网络参数须逐项审核。恢复后保持 `stopped`，完成控制器登记、挂载和网络隔离核验，再启网并验收。
